Mark “Eligible” only when all are true:
  • The comment contains a specific technical claim, not praise or style preference.
  • The supplied excerpts contain enough evidence to judge it.
  • You can rewrite it as one short factual sentence.
  • That sentence is true before merge and false after merge.
  • It fits one of the five claim families below.
Show a concrete example

Comment: “Empty names are accepted here.” Before: the function stores the name without checking it. After: the function rejects an empty name. Decision: Eligible = Yes; normalized claim = “The function accepts an empty name”; family = missing guard; present before = Yes; absent after = Yes.

Show the five claim-family definitions
behavior_inversion
The code does the opposite of the behavior described or intended.
missing_guard
A required validation, condition, or early return is absent.
incorrect_call_relationship
The claim concerns which function calls, wraps, awaits, or delegates to another.
causal_mislocalization
The observed behavior is real, but the comment attributes it to the wrong code or cause.
stale_evidence
The claim refers to code or behavior that is no longer present in the compared snapshot.
